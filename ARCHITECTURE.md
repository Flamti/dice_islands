# ARCHITECTURE.md — утверждённая архитектура Dice Islands

Утверждено геймдизайнером 2026-07-25. Изменения этого документа — только через явное решение геймдизайнера.

## 1. Принципы

- **Вся игровая логика — в изолированном C++ ядре** (EnTT ECS, GDExtension). Godot — только рендер, звук, UI, ввод.
- **Единственная граница** движок ↔ ядро — адаптер (`core/src/adapter/`): внутрь передаются только плоские данные (dt, ввод/намерения, ссылки на загруженные ассеты), наружу — дельты стейта и события.
- **Независимая математика** (`core/src/math/`): собственные векторы/шум/RNG, никаких типов Godot ниже адаптера. Ядро и тесты собираются без Godot.
- **Данные, не код:** весь баланс — в `data/*.json`; в коде нет магических чисел.
- **Детерминизм:** ядро детерминировано по сиду; истинный стейт и RNG — только на хосте (host-authoritative, listen server, ENet).
- **ECS-дисциплина:** компоненты — плоские structs без логики; системы — изолированная логика; сущности — ID.

```

│   ├── SConstruct             # сборка SCons (стандарт godot-cpp)

│   │   ├── math/              # векторы, шум (Simplex), RNG — без типов Godot

│   │   ├── systems/           # economy, dice, danger, combat, victory, ...
│   │   ├── turn/              # Turn State Machine, фазы 0–9, барьеры, таймеры

│   └── tests/                 # unit-тесты ядра, без Godot
├── game/                      # Godot-проект — только визуал, звук, UI
│   ├── project.godot
│   ├── addons/dicecore/       # собранная .so + .gdextension-манифест
│   ├── scenes/                # лобби, карта, остров, наблюдение боя
│   ├── scripts/               # GDScript
│   ├── ui/
│   └── assets/                # заглушки моделей, атласы, звук

│   ├── research.json   combat.json  generator.json
└── scripts/                   # build.sh, test.sh, headless-проверка .gd
```

## 3. Архитектура данных

Классической БД нет — одиночный процесс без серверной персистентности. Два слоя файлов:

1. **Конфиги баланса `data/*.json`.** Здания, грани кубиков, катастрофы, исследования, статы бойцов, параметры генератора. Загружаются ядром при старте партии; геймдизайнер правит числа без перекомпиляции. JSON: человекочитаем, диффается в git.
2. **Снапшоты сейвов.** Полный стейт ECS + состояние RNG + сиды + номер хода; поле версии формата обязательно. MVP-формат — **JSON** (приоритет — отладка и диффы); переход на бинарный формат — после MVP, поле версии это допускает. Точка сохранения — только граница хода (фаза 0), на хосте.

## 4. Сеть (фиксация решений SPEC §12)

- Host-authoritative listen server, Godot High-Level Multiplayer API (ENet).
- Клиенты шлют намерения (`BuildIntent`, `RerollIntent`, `RaidIntent`, `PhaseReady`, …); хост валидирует в ядре, применяет, рассылает подтверждённые дельты. ИИ подаёт намерения на хосте через те же интерфейсы.
- Полный снапшот — при подключении/реконнекте; бой — потоком событий симуляции.

## 5. Зависимости

| Зависимость | Способ подключения | Назначение |
| --- | --- | --- |
| godot-cpp (ветка 4.7) | git-сабмодуль `core/extern/godot-cpp` | биндинги GDExtension |
| EnTT | git-сабмодуль `core/extern/entt` | ECS (sparse sets), header-only |
| Godot 4.7.1 | `resources/` (вне git) + системный PATH | движок, headless-проверки |

Версии фиксируются коммитами сабмодулей; обновление версий — отдельное решение, не побочный эффект этапа.
